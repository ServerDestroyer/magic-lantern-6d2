# BLOCKING CONSTRAINTS — Read Before Anything Else

> Each was discovered through an actual failure this session, and three of them
> produced wrong conclusions that reached project documentation. This handoff was
> itself adversarially verified afterwards and **eight of its own claims were
> wrong** — that is why the constraints below are phrased as habits, not facts.

- [ ] CONSTRAINT: **Never read `sd.qcow2` while qemu is running.** You get a
      half-flushed image whose tail reads as NULs at a 16 KiB FAT-cluster
      boundary. It looks exactly like a truncated write and is not one; this was
      written up as a qemu-eos SD DMA bug that does not exist. Let the runner
      exit, confirm with `pgrep -f 6D2.111/build/sd.qcow2`, then read.
- [ ] CONSTRAINT: **Use `grep -a` on the log files.** `DEBUGMSG.LOG` contains NUL
      padding, so plain `grep` treats it as binary and silently reports nothing.
      That produced a false "zero MPU messages captured" finding.
- [ ] CONSTRAINT: **A measurement beats a code-reading argument.** Five parallel
      agents reading source produced five confident, wrong root causes. One
      qemu-monitor probe settled it in a single boot. Probe guest state before
      theorising — see Techniques.
- [ ] CONSTRAINT: **Everything here is shared with concurrent sessions** — not
      just the gitignored `ml/` and `qemu-eos/` clones but tracked paths too
      (`tools/`, `patches/`, `.planning/`). Files changed under this handoff
      while it was being written. Re-stat and re-read before trusting any
      statement below, and `git status` before blaming your own edits.
- [ ] CONSTRAINT: **RAM addresses are valid only for the exact binary that
      produced them.** Any edit shifts every symbol. Re-run `arm-none-eabi-nm`
      after every rebuild; never reuse an address from a document.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Live-image read | Reading `sd.qcow2` before qemu flushed it; tail reads as NULs at cluster granularity | blocking | Exit qemu, verify with `pgrep`, then `guestfish`/`qemu-img` |
| Binary-file grep | `grep` on NUL-padded logs reports nothing, not an error | blocking | Always `grep -a` |
| Theory over measurement | Confident root causes derived from reading code, all wrong | blocking | Probe guest state via qemu monitor first |
| Attributing without an A/B | Blaming a regression on the most recent visible change | blocking | Run the controlled build before writing the cause down |
| Stale RAM addresses | Reusing addresses across builds | advisory | Re-resolve with `nm`/`addr2line` against the current ELF |

## Techniques Worth Keeping

Probe ML from the host over the qemu monitor — works even when the guest stops
progressing, and settles in one boot what code-reading cannot:

```
xp/1xw <sym>                 # one read PER SYMBOL: diag_entered, diag_appended,
                             # diag_drop_nobuf, diag_drop_full, diag_lock_enter,
                             # diag_lock_exit, buf, buf_size, len.
                             # The BSS block is INTERLEAVED by the linker —
                             # do not read it as one ordered run.
xp/4xw <diag_total_before>   # total_before, free_before, total_after, free_after
                             # (~0x334 away from the counters above)
x/3xw 0xdf006e6c             # want c004f8df bf004760 <my_DebugMsg>
pmemsave <buf> <len> out.log
```

Re-resolve every address with `arm-none-eabi-nm` after each rebuild.
`tools/grab_log.py` automates the `pmemsave` step only — it does not read the
counters or check the patch; run those by hand.

Note the failure mode is silent: a NULL `buf` means no `DEBUGMSG.LOG` and **no
DIAG trailer** (`log_finish()` only writes it `if (buf && buf_size - len > 300)`,
log-d678.c:452). Absence is the failure signal; the pool numbers must come from
the four `diag_*_before/after` words.
